# Ordinary-execution discovery study

See [the implemented workflow](../../docs/NATIVE-SEMANTIC-DISCOVERY.md) for scope and record contracts. This directory contains explicit corpus extraction, installed-wheel staging, a one-lease worker, and exact-job result collection.

The first study uses Qwen2.5-1.5B base, eager FP32 CUDA, batch one, source-document splits and raw repository prose/code. A six-document mechanics smoke and a disjoint twenty-document exploration share no source groups. No semantic labels, answer tables, manually selected attention heads, source annotations or model edits enter discovery.

The scientific question is whether learned features and source/read predictions improve fresh native computation forecasts beyond linear features, unchanged state, discovery-mean writes and position-only attention. The paid native-neuron ridge diagnostic answers a different local-input question. Report each document/span and retain all candidate trajectories. Output-head KL compares consequences through the original frozen native norm/head, whose cost is counted.

The worker has a finite science wall bound and no retries. Capture/identity/split/finite-value mechanics can stop invalid execution. Forecast scores cannot erase a mechanically valid trend. The public training controller's development policy selects a reversible continuation branch, preserving rejected states.

Artifacts belong under the explicitly supplied stage and scratch locations, not in source control. `collect.py` saves the original job's metadata, logs, admission receipt and result marker. The marker pins a complete evidence archive; transfer that exact archive directly from its host, verify its SHA-256, and run `mdb analyze verify` after extraction. No private workspace runtime imports are staged.
